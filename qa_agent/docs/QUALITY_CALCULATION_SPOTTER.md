# Расчёт качества для проекта Spotter (аудиосегменты)

## 🎯 Суть метода

Для проекта **"Выделение споттерных слов на аудио"** используется **consensus-based подход** с учётом временной толерантности.

---

## 📊 Как считается Score (качество)?

### Шаг 1: Парсинг меток

Каждая метка разметчика имеет формат:
```json
{
  "type": "keyword",
  "entityId": "word_1",
  "position": {
    "start": 1.23,    // секунды
    "finish": 2.45    // секунды
  }
}
```

Разметчик может выделить несколько сегментов в одном задании.

---

### Шаг 2: Определение правильного ответа (reference)

Есть два варианта:

#### Вариант A: Golden ответ (если есть)

Если в задании есть золотой ответ (`GOLDEN:marks`), он используется как эталон.

#### Вариант B: Consensus (если golden нет)

Если golden нет, **находим мажоритарный ответ** (consensus):

1. **Сравниваем каждую разметку со всеми остальными**
   - Используем толерантность по времени: **0.15 секунды**
   - Две метки совпадают, если:
     - `type` совпадает (точно)
     - `entityId` совпадает (точно)
     - `|start1 - start2| < 0.15` секунды
     - `|finish1 - finish2| < 0.15` секунды
     - Количество сегментов одинаково

2. **Выбираем разметку с максимальной поддержкой**
   - Считаем для каждой разметки, сколько других с ней согласны
   - Берём разметку с наибольшим количеством согласных
   - Это кластер согласных разметчиков

3. **Проверяем размер кластера**
   - Если кластер согласных < 2, **консенсуса нет** → задание пропускается
   - Если кластер ≥ 2, используем его как reference

---

### Шаг 3: Фильтрация заданий

Задание пропускается, если:

1. **Перекрытие < 5 разметчиков** (`MIN_MARKERS = 5`)
2. **Нет консенсуса** (кластер согласных < 2)
3. **Низкая согласованность** (< 80%, `CONSISTENCY_THRESHOLD = 0.8`)

**Согласованность задания** = доля разметчиков, совпавших с reference.

---

### Шаг 4: Вычисление Score для разметчика

Для каждого assignment разметчика:

```python
score = 1  если marks_match(ответ_разметчика, reference)
score = 0  если не совпадает
```

**`marks_match()`** проверяет:
- Одинаковое количество сегментов
- Каждый сегмент совпадает по `type`, `entityId`
- Временные метки отличаются не более чем на **0.15 секунды**

---

## 📈 Пример расчёта

### Задание с 5 разметчиками:

```
item_id: audio_123

Разметчик A: [{"type": "keyword", "entityId": "word_1", "position": {"start": 1.20, "finish": 2.40}}]
Разметчик B: [{"type": "keyword", "entityId": "word_1", "position": {"start": 1.23, "finish": 2.45}}]
Разметчик C: [{"type": "keyword", "entityId": "word_1", "position": {"start": 1.22, "finish": 2.42}}]
Разметчик D: [{"type": "keyword", "entityId": "word_2", "position": {"start": 3.00, "finish": 4.00}}]
Разметчик E: []  (ничего не выделил)
```

### Шаг 1: Поиск консенсуса

Сравниваем разметки:
- **A, B, C** совпадают (временные метки в пределах 0.15 сек)
- **D** - отличается (другой entityId)
- **E** - пустой ответ

**Кластер согласных: A, B, C** (размер = 3 ≥ 2) ✅

**Reference = разметка A** (или B, или C - они все совпадают)

### Шаг 2: Согласованность задания

```
Согласованность = 3/5 = 0.60 (60%)
```

**0.60 < 0.80** → задание пропускается ❌

---

### Пример 2: Хорошее задание

```
item_id: audio_456

Разметчик A: [{"type": "keyword", "entityId": "word_1", "position": {"start": 1.20, "finish": 2.40}}]
Разметчик B: [{"type": "keyword", "entityId": "word_1", "position": {"start": 1.23, "finish": 2.45}}]
Разметчик C: [{"type": "keyword", "entityId": "word_1", "position": {"start": 1.22, "finish": 2.42}}]
Разметчик D: [{"type": "keyword", "entityId": "word_1", "position": {"start": 1.25, "finish": 2.43}}]
Разметчик E: [{"type": "keyword", "entityId": "word_1", "position": {"start": 1.21, "finish": 2.41}}]
```

**Кластер согласных: A, B, C, D, E** (размер = 5) ✅

**Согласованность = 5/5 = 1.00 (100%)** ✅

**Reference = разметка A**

### Score для каждого:
- Разметчик A: **score = 1** (совпадает с reference)
- Разметчик B: **score = 1** (|1.23-1.20|=0.03 < 0.15)
- Разметчик C: **score = 1**
- Разметчик D: **score = 1**
- Разметчик E: **score = 1**

**Средний score задания = 1.0 (100%)**

## 🔧 Параметры

| Параметр | Значение | Описание |
|----------|----------|----------|
| `MIN_MARKERS` | 5 | Минимальное перекрытие для расчёта consensus |
| `CONSISTENCY_THRESHOLD` | 0.8 | Минимальная согласованность задания (80%) |
| `TIME_TOLERANCE_SEC` | 0.15 | Толерантность по времени (секунды) |

---

## 📊 Итоговые метрики

### На уровне пула (задачи):
- **total_assignments** - всего assignments
- **total_items** - всего заданий
- **average_quality** - средний score по всем assignments

### На уровне разметчика:
- **marker_id** - ID разметчика
- **total_assignments** - количество assignments
- **quality** - средний score разметчика (доля правильных ответов)
- **correct_assignments** - количество правильных assignments
- **incorrect_assignments** - количество ошибок

---

## 🎯 Ключевые особенности

1. **Временная толерантность 0.15 сек**
   - Учитывает, что разметчики могут немного по-разному выделять границы
   - Если разница < 0.15 сек → считается совпадением

2. **Consensus вместо golden**
   - Если нет эталона, берём мажоритарный ответ
   - Требуется минимум 2 согласных разметчика

3. **Фильтрация низкокачественных заданий**
   - Задания с низкой согласованностью (<80%) исключаются
   - Не влияют на итоговый score разметчиков

4. **Множественные сегменты**
   - Разметчик может выделить несколько сегментов
   - Все должны совпадать для score=1

## 📝 Что попадает в Excel отчёт

### Лист "Качество":
- Статистика по пулу (общая)
- Статистика по каждому разметчику (quality, количество заданий)

### Лист "Проблемные задания":
- Задания с низкой согласованностью (<80%)
- Показывает ответы всех разметчиков для анализа

### Лист "Комментарии":
- LLM объяснения для ошибочных assignments (score=0)
- Сравнение ответа разметчика с правильным

### Лист "Обратная связь":
- Персональные сводки для каждого разметчика
- Топ-N ошибок с объяснениями

## 🧪 Пример полного расчёта

### Входные данные:
- 100 assignments
- 20 заданий (по 5 разметчиков на задание)

### Обработка:
1. Фильтрация: осталось 18 заданий (2 пропущены из-за низкой согласованности)
2. 90 assignments после фильтрации (18 заданий × 5)

### Результаты по разметчику "marker_123":
- Всего assignments: 18
- Правильных (score=1): 15
- Ошибок (score=0): 3
- **Quality = 15/18 = 0.833 (83.3%)**

### Результаты по пулу:
- Средний quality: 0.85 (85%)
- Проблемных заданий: 2 (низкая согласованность)
- BAD assignments для комментариев: 27 (все со score=0)

## 🔍 Отладка

Если score кажется неправильным, проверьте:

1. **Временные метки**
   - Логи показывают сравнение меток
   - Проверьте разницу по `start` и `finish`

2. **Формат меток**
   - Должен быть список словарей с `type`, `entityId`, `position`
   - JSON парсинг может упасть на некорректных данных

3. **Консенсус**
   - Проверьте размер кластера согласных
   - Если < 2, задание пропускается

4. **Согласованность**
   - Если < 80%, задание исключается
   - Проверьте `mean_consistency_by_item` в логах
