# Отслеживание обработанных assignments

Система отслеживания предотвращает повторную обработку одних и тех же assignments при следующих запусках.

## Структура

Для каждого проекта создается файл:
```
state/processed_assignments/{project_id}.json
```

Формат:
```json
{
  "project_id": "d8f48f67-...",
  "last_updated": "2026-05-31T15:30:00",
  "tasks": {
    "task_abc123": {
      "task_name": "Спот терные слова пул 1",
      "processed_assignments": [
        "assignment_id_1",
        "assignment_id_2",
        ...
      ],
      "last_processed": "2026-05-31T15:30:00",
      "total_processed": 150
    }
  }
}
```

## Логика работы

1. **При загрузке assignments** (stage "quality"):
   - Читаем список обработанных `assignment_id` из файла
   - Фильтруем: оставляем только новые assignments
   - Обрабатываем только новые

2. **После успешной обработки** (stage "summary"):
   - Добавляем `assignment_id` обработанных assignments в файл
   - Обновляем timestamp

3. **При повторном запуске**:
   - Система автоматически пропустит уже обработанные assignments
   - Обработает только новые

## Пример

### Первый запуск (31 мая):
- Скачано 1000 assignments
- Обработано 1000
- Сохранено 1000 assignment_id

### Второй запуск (1 июня):
- Скачано 1500 assignments (та же задача продолжает размечаться)
- Отфильтровано 1000 (уже обработаны)
- Обработано только 500 новых
- Сохранено еще 500 assignment_id (итого 1500)

## Где хранятся ID

Файлы отслеживания НЕ удаляются автоматически. Они накапливаются для истории.

Чтобы **сбросить** и обработать все заново - удалите файл:
```bash
rm state/processed_assignments/{project_id}.json
```
