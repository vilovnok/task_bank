## 🔍 Логика проверки (код)

```python
def should_process_task_today(task: Dict, task_state: Dict, run_date: str) -> bool:
    """
    Проверяет, нужно ли обрабатывать задачу сегодня.
    
    Returns:
        True - обработать
        False - пропустить
    """
    # Проверка 1: Уже обработана сегодня?
    if task_slice_completed_today(task_state, run_date):
        return False  # ⏭️ Пропускаем
    
    # Проверка 2: Задача полностью завершена?
    if task_state.get("fully_analyzed") and task.get("is_done"):
        return False  # ⏭️ Пропускаем
    
    return True  # ✅ Обрабатываем


def task_slice_completed_today(task_state: Dict, run_date: str) -> bool:
    """
    Проверяет, был ли успешно обработан slice за сегодня.
    """
    slice_info = task_state.get("slices", {}).get(run_date)
    
    if not slice_info:
        return False  # Slice не существует → НЕ обработано
    
    return slice_info.get("status") == "completed"  # Проверяем статус
```

## 🛡️ Гарантии безопасности

✅ **Дедупликация по (project_id, task_id, date)**
   - Каждая задача = уникальный ключ
   - Невозможно обработать дважды в один день

✅ **State сохраняется сразу после обработки**
   - Даже если процесс упадёт, обработанные задачи уже записаны
   - При перезапуске они будут пропущены

✅ **Atomic write**
   - State сохраняется атомарно (через временный файл)
   - Нет риска повреждения данных

✅ **Проверка на уровне логики**
   - Проверка происходит ДО запуска pipeline
   - Не тратятся ресурсы на повторную обработку

## 📊 Мониторинг дедупликации

### Проверить обработанные задачи за сегодня:

```bash
cat state/qa_agent_state.json | jq '.projects[].tasks[] | select(.slices["2026-06-01"].status == "completed") | {task_id, task_name}'
```

### Посмотреть все slices для задачи:

```bash
cat state/qa_agent_state.json | jq '.projects[].tasks["7f2f0bb6"].slices'
```

### Проверить логи пропусков:

```bash
grep "SKIP already processed" logs/qa_manager.log
```

## 💡 Важные моменты

1. **State файл - источник правды**
   - Если удалить state файл, все задачи будут обработаны заново
   - Делайте бэкапы state файла

2. **Дата берётся из системы**
   - run_date = today_str() = "YYYY-MM-DD"
   - Смена даты происходит в 00:00 по времени сервера

3. **Полная обработка = один slice в день**
   - Один pipeline run = один slice
   - Завтра будет новый slice с новой датой

4. **Совместимость с FIR**
   - Отчёты на FIR тоже организованы по датам
   - Каждый день = новая папка на FIR
